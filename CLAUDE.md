# snow-wx — notes for Claude Code

Public website of open weather, snowpack and avalanche data for western US ski areas, built for skiers and
snow-science users. A team of 3 developers works on it (ownership: `CONTRIBUTING.md`).
**Scope (Nov 23 2026):** ski-area forecasts (NBM + model plumes) and SNOTEL observations. Model maps and
Sno-Parks are being removed; SNOTEL-site forecast *pages* go, but NBM forecasts at SNOTEL sites stay computed and
archived (verification needs them).
**Hosting today:** GitHub Actions builds static JSON/PNG + HTML and deploys to GitHub Pages. **Moving to** GitLab +
Cloudflare (Workers Static Assets, R2, D1, Containers/Workflows, WX API Worker): `docs/specs/platform-transition.md`.

## Hard rules (PLAN §0; verbatim there)
1. Safety info (avalanche danger, NWS alerts, snow level/rain-at-base, data freshness) is never gated or hidden.
2. Never present a heuristic as an accuracy claim or an avalanche rating. Label heuristics.
3. Open, license-clean data only; keep attribution on pages and charts.
4. One accumulation period per chart axis; **never sum, scale or interpolate percentiles across windows** (ranges come
   from one native NBM window); default uncertainty is **p25–p75 ("likely")**; 10–90% only where explicitly noted;
   sources + issue times on every module. (Documented exception: the 12-h day/night ranges add 6-h windows rank by rank,
   a conservative approximation; 7/10-day totals show the expected amount only.)
5. Sources fail independently; fetch separate from pure functions; offline tests with fakes.
6. Stay within static-host limits (20,000 files/deploy, 25 MiB/file) — bulk data goes to R2.

## Layout
- `pipeline/` — one module per source, each with `run(cfg, session, outdir) -> dict`, registered in `pipeline/__main__.py:SOURCES`.
  `nbm/` (inventory, fetch, decode, points; overlays in `layers.py`), `points.py` + `summary.py` (pure maths and Daily Snow rules),
  `ecmwf.py` / `gefs.py` / `fetch_resilient.py` (plumes), `models/` (map rendering *(being removed)* **and** the plume/ridge
  samplers `multimodel.py`, `ridge.py`), `snotel.py`, `alerts.py`, `avalanche.py`, `archive.py`, `verify.py`, `monitor.py`,
  built-but-off `pages.py`, `pwa.py`, `og.py`, `alerts_backend.py`, `wind_exposure.py`, `r2_plan.py`, `stub.py`.
- `web/` — static site (Leaflet, Plotly, MapLibre self-hosted in `web/vendor/`; plain JS, no build step). `web/js/colors.js` holds
  the single NWS snowfall table; `web/js/charts/theme.js` the shared chart theme.
- `config/settings.yml` (region, windows, flags; prefer config over code), `config/models.yml`, `config/sources.yml`, `config/summary_rules.yml`.
- `data/ski_areas.json`, `data/snotel_points.json` — committed catalogs (ODbL / public domain).
- `tests/` (pytest; extend `tests/fakes.py` for new sources), `tools/` (browser checks, fixtures, inventories, rehearsals).
- `infra/scheduler/` — Cloudflare Worker that dispatches workflows on time (built, NOT deployed; fix review M14/M10 first).

## Conventions
- Keep fetch code separate from pure processing functions; test the pure parts.
- Write JSON via `common.write_json` (rounds floats, NaN → null; pass `ndigits=5` for coordinates).
- US units on the site (in, °F, mph; kt on ASOS).
- Polite User-Agent (config `http.user_agent`) and few requests per run.
- The forecast archive is additive: never rename or drop columns; loaders must tolerate older files.
- about.html must be updated whenever a method changes.

## Data licensing (full table: PLAN §10)
- OK: NOAA/NWS (NODD on AWS, api.weather.gov), USDA NRCS AWDB, IEM, ECMWF open data (CC BY 4.0, attribute), USGS.
- Not used: Synoptic; Open-Meteo API (free tier non-commercial; prototype only).
- MADIS: only distribution category 3 ("Public – full distribution").
- avalanche.org: show ratings unaltered, grey out expired ratings, always link the center's full forecast.
- OpenStreetMap / OpenSkiMap: ODbL, keep attribution.
- Ask before adding any source whose terms are unclear. No scraping.

## NBM and point-forecast gotchas (spec: `docs/specs/data-pipeline.md`; layouts: `docs/nbm_inventory.md`)
- Layouts differ by cycle — never assume one. 01/07/13/19Z core has ASNOW 6/24/48/72-h percentiles + exceedances, SNOWLVL
  and SNOWLR percentiles to ~f263, hourly files to f264, no qmd; 00/06/12/18Z have snowfall percentiles only to f048/f054 but
  carry qmd (QPF percentiles). Only windows ending at the file's own hour count.
- **On 01/07/13/19Z cycles 6-h windows end at f005, f011, …; past f036 index them with `h + (-(init.hour + h) % 6)`**
  (review H1: two places still use `h + (-h % 6)`).
- **core GRIB uses alternativeRowScanning** (odd rows reversed; qmd does not): index with `run.flat_index`.
- SNOWLVL is metres MSL; ecCodes names SNOWLVL/SNOWLR `unknown`. Missing messages are missing data (fail > 20 %).
- Cycle order: newest complete 01/07/13/19Z → previous full-suite (≤ 12 h old) → 00/06/12/18Z; QPF percentiles come from the
  newest synoptic cycle with complete qmd (`liquid_cycle`).
- Methods: lapse 6.5 °C/km grid → point (cap 4000 ft); P(snow) = P(snow level < point); day/night 00Z–12Z / 12Z–00Z for temps
  and snow type; snow charts use 12Z–12Z days; ranges only from native windows (`points.native_window`).
- Check decodes against the NBS text bulletins (`blend.YYYYMMDD/HH/text/blend_nbstx.tHHz`).

## Reusable gotchas
- Lighthouse: `PATH=/c/miniforge3/envs/tools:$PATH npx -y lighthouse@12.6.1 URL --only-categories=performance,accessibility`
  against a gzip server of `build/`; target median of ≥ 3 interleaved runs ≥ 85. The obs map scores bimodally (tile timing).
- Browser checks: `Page.navigate` with only a hash change does not reload; element screenshots via CDP clip after
  scrollIntoView without `captureBeyondViewport`. No fixed sleeps: wait for the page's READY signal, poll background work.
  Re-record fixtures only with `tools/browser_fixtures.py record`.
- Tests must never write the real `data_cache` (autouse fixtures patch `REPO_ROOT`).
- Safari: feature guards use `typeof x === "function"`, never `"x" in window`.
- Maps: obs-map symbols draw on one canvas; overlays on a view-sized canvas, never a whole-West `L.ImageOverlay`.
  `basemap.js snowTileLayer` fills USGS z9 holes from ancestor tiles.
- Finder: keep the first paint static or CLS jumps.
- ECMWF: member counts are read from the data (the mirror has 50 perturbed members, no control); AIFS tp is mm, IFS tp metres.
- GitHub: no `gh` CLI on the dev PC; read run status via the public REST API. The forecast archive never lives on a PC.
