### 5.10 Site, hosting & SEO architecture (W1–W2) — *new*
- **Split site and data.** Static shell (HTML/CSS/JS, rarely deployed) on
  **Cloudflare Pages**; frequently-updated data (points, obs, model frames) in
  **R2** served from `data.<domain>` and updated by Actions.
  - Facts to design around: Pages free plan allows **20,000 files per
    deployment**, **25 MiB per file**, **500 git builds/month**, with unmetered
    static bandwidth; Pages Functions/Workers free = 100,000 requests/day.
    Model-map frames likely exceed 20,000 files → R2. Confirm how
    direct-upload deploys count toward builds **[verify]**; check Cloudflare's
    terms for image-heavy sites **[verify]**.
  - Keep the Actions pipeline; GitHub Pages remains only as a redirect/canonical
    stub to the new domain.
- **Prerendered area pages** `/ski/<state>/<id>/` (and `/snopark/…`) generated by
  `pipeline/pages.py`: `<title>`, meta description (= daily summary), `<h1>`,
  summary text, canonical, JSON-LD (WebPage/Place), OG image; JS hydrates charts
  from `data.<domain>`. Plus `sitemap.xml`, `robots.txt`, a data-status page,
  and `#id` → path redirects. ~161 + ~450 pages × < 15 KB.
- **OG share cards:** 1200×630 per area (name, 72 h expected, snow level); top
  60 areas first.
- **Performance:** area page LCP < 2.5 s on 4G; obs map Lighthouse mobile ≥ 85.

### W1 cutover checklist (add items as they are found)
- [ ] **Live origin in config/CI:** set `site.origin` in `config/settings.yml` (or the `SITE_ORIGIN` env/variable in the
  workflows) to the new domain. It is used by `pipeline restore` (previous good SNOTEL copy + meta.json history, fetched from the
  live site before each build) and `pipeline.monitor` (live meta.json). While both domains exist, keep restoring from whichever
  one serves the newest deploy; after the cutover GitHub Pages is only a redirect stub and must NOT be the origin.
- [ ] First build after the cutover: confirm `restore` logs stations restored (or "no copy" deliberately) and the monitor job
  reads the new meta.json.
- [ ] Data origin (R2) vs site origin: if `data/` moves to a data domain, `restore` and `monitor` need that origin instead.
